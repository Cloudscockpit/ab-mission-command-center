# Mission Plan — Standalone Mobile-Responsive Visual Mission Analytics Dashboard (v1.2.0)

> Mission: `urn:voltron:mission:mission-analytics-dashboard-v1-2-0` · Date: 2026-10-26 · Status: awaiting go/no-go

Every completed mission will also write `mission-report.html`, a single self-contained, mobile-responsive, offline dashboard, next to `mission-report.md` and `mission-report.jsonld`. It shows the mission header and status, four KPI figures, the workload of the five Agents as an inline SVG donut, the five-stage maturity as progress meters, and the touched files as an accordion with one-click path copy. A stdlib-only Python renderer produces it from the report graph, `.actionboard/registry.json` and a small metrics file, and Black Agent's report flow calls it on every `/start-mission` in all four CLIs. The visual standard is Linear/Vercel-grade dark mode, applied under the Hallmark design skill.

No mission brief was written for this mission; the slug above was derived once from the objective's title and is the identifier the report must reuse. Documents go to `docs/missions/2026-10-26-mission-analytics-dashboard-v1-2-0/`, the directory convention the two earlier missions already use.

## Design and data decisions to confirm at the gate

These settle points where the request, the Hallmark floor and the available data pull in different directions. Reply **edit <section>** to change any of them.

1. **Labels follow the Hallmark floor, not the request's capitals.** Hallmark forbids labels in tracked capitals, middle-dot-joined meta strings, and decorative status dots (floor rules 9 and 10). The status badge therefore reads "Clean run" or "Retried" in sentence case with no dot, and the header shows Mission ID, Operator level and timestamp as separate labelled fields rather than one dotted string.
2. **No invented figures.** The "14m 32s" and "3/3 Autonomous Unlocked!" in the request are examples. Every figure comes from a real source, and a figure with no source renders as "Not recorded" (floor rule 8). The celebratory "Autonomous unlocked" wording appears only when the gate verdict for that action is actually `autonomous`.
3. **Where the numbers come from.** Assignment statuses, results and file lists come from `mission-report.jsonld`. Maturity stages, pass rates, clean runs and execution mode come from `.actionboard/registry.json` through the existing `maturity.py` logic. Duration, tests passed and the add/edit/delete file counts are not stored anywhere today, so Black Agent writes a small `mission-metrics.json` through a `metrics` subcommand: start time recorded at the "go" approval, end time at report time, file statuses from `git diff --name-status`, and test counts taken from Yellow Agent's report.
4. **"Workload" means assignments.** The donut shows each Agent's share of the mission's dispatched assignments, with files touched and outcome shown beside it. File counts alone would hide Green Agent, which is read-only.
5. **Fonts are stacks, not downloads.** `Geist Mono`, `JetBrains Mono` and Inter are named first in the font stacks, falling back to `ui-monospace` and the system UI font. Embedding font files would add roughly 100 KB or more to every report, so it is left out unless you want it.
6. **No-JavaScript still works.** The accordion is a native `<details>` element, so all content is readable with scripting off. JavaScript only adds the copy button and nothing else.
7. **The zero-network guarantee is enforced twice.** The page carries a Content-Security-Policy meta tag with `default-src 'none'` and hash-pinned inline script and style, and a test scans for any URL, `@import`, `fetch` or similar.
8. **The Black segment is rendered light grey.** Black on a `#0a0c10` background would be invisible. The other four Agents get distinct hues, and every segment is also directly labelled so colour is never the only signal.

## Risk Register

| Category | Risk | Sev | Mitigation |
|---|---|---|---|
| technical | Python 3.9 incompatibility in the new script (the 1.1.0 mission lost a CI round to exactly this) | M | Standard library only, no `match`, no `X \| Y` type unions, no `str.removeprefix`; the report tests run on the full 3.9–3.12 CI matrix; Red Agent runs the suite under 3.9 before reporting. |
| technical | Agent-written text, file names or mission titles carry HTML or script into the dashboard | H | `html.escape` on every string in both element and attribute contexts, a CSP with hash-pinned inline script and `default-src 'none'`, escaping tests with hostile fixtures, and a Yellow Agent security review. |
