# Mission Plan — Zero-Footprint Installer and NPX Zero-Clone Package (v1.1.0)

> Mission: `urn:voltron:mission:zero-footprint-installer-npx-zero-clone-v1-1-0` · Date: 2026-10-26 · Status: awaiting go/no-go

Eliminate installation clutter from the user's project for Codex CLI, Antigravity CLI and OpenCode: the git-clone one-liner removes its own clone after installing, uninstall works without the clone, and a new npx/uvx wrapper installs from a release bundle downloaded to the OS temp directory, so no repository is ever left in the project.

No mission brief was written for this mission; the slug above was derived once from the objective and is the identifier the report must reuse.

## Risk Register

| Category | Risk | Sev | Mitigation |
|---|---|---|---|
| data-loss | --cleanup deletes a directory that is not the throwaway clone, such as a developer checkout or the user's own project | H | Delete only a strict subdirectory of --project that is a git work tree with the expected origin; refuse when the path equals or contains the project; tests cover every refusal. |
| data-loss | Cleanup removes a clone holding local edits or the user's agentformation.config.json | M | Refuse when `git status --porcelain` is non-empty or --config resolves inside the clone; print why and leave the clone. |
| technical | rmtree fails on Windows because .git object files are read-only, leaving a half-deleted clone | M | Use an onerror handler that clears the read-only bit and retries; on any remaining failure print the path and exit 0 since the install itself succeeded. |
| integration | The @actionboard npm scope is not owned, so `npx @actionboard/install` cannot be published as named | H | User registers the scope or chooses another name before publishing; fallback is `npx <release .tgz URL>` attached to the GitHub release; the README states which command is live. |
| integration | No git tags or releases exist, so the wrapper's download returns 404 until v1.1.0 is tagged | H | Wrapper reports a clear error naming the missing tag; ACTIONBOARD_BUNDLE override for tests and smoke; tag and release are a listed user step. |
| technical | npx users without Python 3.9+ cannot run the wrapper, since it delegates to scripts/install.py | M | Wrapper detects python3, python and py -3 and exits with an install hint; accept the dependency rather than porting the installer to Node this mission. |
| technical | Tarball extraction allows path traversal or differs across platforms | M | Extract with Python tarfile using the 'data' filter, available on every supported Python patch release; Yellow security-reviews. |
| integration | Remote code is downloaded and executed without integrity checks | M | Pin the download to the wrapper's own version tag over HTTPS; accept and monitor for 1.1.0, with a SHA-256 manifest proposed for the next release. |
| integration | Existing users who keep a clone for updates see changed behaviour | M | --cleanup is opt-in and only the new one-liner passes it; old commands behave as in 1.0.0; a regression test asserts identical output without the flag. |
| data-loss | Projects installed with 1.0.0 have no standalone uninstaller once their clone is deleted | L | The manifest location is unchanged, so `npx @actionboard/install --uninstall` and a fresh clone both still uninstall them; documented in the README. |
| technical | The temp directory is left behind when the wrapper is interrupted | L | Remove it in a finally block and on SIGINT; temp dirs live under os.tmpdir(), which the OS reclaims. |
| scope | PyPI publishing, a Node port of the installer, and signed bundles creep into this mission | M | Out of scope: uvx runs from the git subdirectory, the installer stays Python, signing is deferred. |
| scope | The registry is credited with an autonomous-mode unlock the run history does not support | L | Maturity comes from the scored run history in the report, never asserted in advance. |
| technical | Live smoke runs fail on CLI authentication or cost more tokens than expected | L | Green confirms auth first; one short prompt per CLI; failures are recorded, not retried in a loop. |
