That Files owned column is the whole trick. Red and Blue hold different files, so they run at the same time and cannot collide; Yellow waits because it depends on both. Ownership is checked before dispatch rather than discovered later as a merge conflict.

Setup · four CLIs

Install it in under a minute

One source, built for each CLI. Claude Code and Cowork install the plugin from the marketplace; OpenCode, Codex and Antigravity use the installer, which needs Python 3.9+ and records every file it writes so --uninstall removes exactly those.

Claude Code

Terminal

Run these two commands in any session:

/plugin marketplace add Cloudscockpit/ab-mission-command-center
/plugin install actionboard-v5-agentformation@actionboard-v5-agentformation

If the install summary says Run /reload-plugins to activate., run /reload-plugins. Otherwise it is already live.

Confirm it loaded:

claude plugin details actionboard-v5-agentformation@actionboard-v5-agentformation

Claude Cowork

No terminal

This happens in the interface, not the chat box — typing the command above into a Cowork message will not work.

  1. Open Customize in the sidebar, then Plugins.
  2. Select Add marketplace and enter
    Cloudscockpit/ab-mission-command-center
  3. Find ActionBoard V5 AgentFormation in the list and select Install.
  4. Open the installed plugin to review its skills and agents before enabling them.

OpenCode · Codex · Antigravity

Installer

Clone once, then install into a project (or --global):

git clone https://github.com/Cloudscockpit/ab-mission-command-center
cd ab-mission-command-center
python scripts/install.py --target opencode --project ../my-app
python scripts/install.py --target codex --project ../my-app
python scripts/install.py --target antigravity --project ../my-app

Run it with no flags to pick from the CLIs it finds on your PATH. It asks before installing Graphify or enabling terse output, and adds the Context7 MCP server. On Codex, trust the hooks once with /hooks.

Then, in any of them: type /start-mission (on Codex, $start-mission) followed by what you want done, in plain English. On OpenCode, use the interactive TUI: opencode run does not expand commands. You will get the four tables above and a prompt to approve. Nothing is written until you reply go.
Extending · new skills

Teaching the Agents something new

A skill is a folder with one Markdown file. The Agents pick it up automatically once it is registered in the actions map. There are two ways in, depending on whether you want the skill for this mission or for good.

Option A — let ActionBoard V5 build it mid-mission

During Skills Gap analysis, any capability with no registry match is flagged needs-new-skill. ActionBoard V5 asks before creating anything: 

Skills Gap includes 1 new skill: pdf-extraction.
Want me to scaffold it via skill-creator now? (yes / no / skip <name>)

Answer yes and it scaffolds the skill through skill-creator. The new skill becomes available next session (on Claude Code, immediately after /reload-plugins). Good for one-off gaps; it lives in your own skills directory, not in the plugin.

Option B — ship it inside the plugin

Fork the repo and add the skill to the neutral source in src/, so the build ships it to every CLI. Six steps, in order.

Create the folder and SKILL.md

The folder name and the name: in the frontmatter must match exactly. If they differ, the skill is skipped silently — no error, it simply never appears. 

src/skills/changelog-writer/SKILL.md

---
name: changelog-writer
description: Write a release changelog from merged commits,
  grouped by type. Use when the user asks to "write the
  changelog", "what shipped this release", or at the end
  of a mission that touched multiple features.
---

# Changelog Writer

Read the commit range, group by type, write to CHANGELOG.md.
...

Write the description like a trigger, not a summary

The description is the only thing the agent sees when deciding whether to fire the skill. Include the literal phrases a person would actually type. "Writes changelogs" will not trigger; the version above will.

Register it in the actions map

Add an entry to src/skills/skills-registry/actions-map.json. This is what Black Agent consults during Skills Gap analysis — an unregistered skill exists but never gets planned into a mission. 

{
  "action": "changelog-authoring",
  "agent": "yellow-agent",
  "description": "Write a release changelog from merged commits",
  "requiredTools": ["Read", "Bash", "Write"],
  "skills": ["changelog-writer"],
  "status": "covered"
}

Check the capabilities contract

Every tool in requiredTools needs the matching capability in that Agent's neutral frontmatter (capabilities: in src/agents/); the build turns capabilities into each CLI's own tool list. Miss one and the Agent is assigned work it physically cannot do — the mission fails at dispatch, not at plan time. The entry above needs write: true in src/agents/yellow-agent.md, which ships with write: false.

Verify every entry at once rather than by eye:

python3 - <<'PY'
import json, re, os
NEED = {'Read': 'read', 'Glob': 'read', 'Grep': 'read', 'Write': 'write', 'Edit': 'edit',
        'Bash': 'bash', 'WebFetch': 'webfetch', 'WebSearch': 'websearch', 'Skill': 'skills'}
agents = {}
for a in os.listdir('src/agents'):
    fm = re.match(r'^---\n(.*?)\n---', open(f'src/agents/{a}').read(), re.S).group(1)
    n = re.search(r'^name:\s*(.*)$', fm, re.M).group(1).strip()
    caps = re.search(r'^capabilities:\n((?:  .*\n?)*)', fm, re.M).group(1)
    agents[n] = {k for k, v in re.findall(r'^\s+(\w+):\s*(\S+)', caps, re.M) if v != 'false'}

for a in json.load(open('src/skills/skills-registry/actions-map.json'))['actionTypes']:
    miss = {NEED[t] for t in a['requiredTools'] if t in NEED} - agents.get(a['agent'], set())
    if miss:
        print('MISSING', a['action'], '->', a['agent'], sorted(miss))
PY

Reference bundled files through the skill directory

If the skill reads anything shipped alongside it — a template, a reference doc — write the path with {{skill_dir}}. The build swaps in each CLI's install location. A bare relative path resolves against whatever project the user is in and the read fails. 

✗  Read the format reference at references/changelog-format.md
✓  Read {{skill_dir}}/references/changelog-format.md

Bump the version, build, then validate

Raise src/VERSION and rebuild. The build writes the version into every CLI's manifest. The version pins the Claude plugin — users receive an update only when it changes, so a push without a bump sits on GitHub invisibly. 

python scripts/build.py --target all
python scripts/build.py --check
python -m unittest discover -s tests/build
claude plugin validate dist/claude
agy plugin validate --strict dist/antigravity

dist/ is generated and committed; CI fails when it drifts from src/. The build tests lint every target, so a skill that breaks one CLI fails before it ships.

Things that bite

SymptomCause
Skill never appears Folder name and frontmatter name: disagree. They must match character for character.
Skill loads but never fires The description reads like a summary. Put the phrases users actually type into it.
Agent blocked at dispatch A tool in requiredTools has no matching capability in that Agent's capabilities:.
Skill exists but is never planned No entry in actions-map.json, so Skills Gap analysis cannot find it.
File not found at runtime A bundled path written relative instead of through {{skill_dir}}.
Users stay on the old version Pushed without bumping src/VERSION and rebuilding. The version pins the plugin.
Output

Missions leave a record you can query

Every mission document is written twice — Markdown for people, schema.org JSON-LD for machines. That is the open format Google's Knowledge Graph consumes, so output loads into a graph store with no transform step.

Every report also carries a Maturity & Progress Summary: each assignment scored on five stages, clean runs counted in .actionboard/registry.json, and how close each kind of work is to moving from Guided to Actionlist to Autonomous.

Beyond one mission

ActionBoard.ai runs the Agents as a continuous loop

This package gives you one mission at a time, in your CLI, on your machine. ActionBoard.ai is the platform the Agents come from — where a single mission becomes an operating loop that keeps running, learns from each pass, and spans local, cloud, and mobile.

The RAOARA loop · six phases

Every ActionBoard run flows through the same six phases, then feeds what it learned back to the start. Where the plugin stops after the mission report, the loop keeps going.

R 01Recognize

Asks clarifying questions until the goal is scoped.

A 02Acquire

Dispatches sub-agents across docs, web, and APIs.

O 03Organize

Shapes raw data into an Action Graph.

A 04Act

Executes — API calls, deploys, writes back.

R 05Review

Audits for accuracy, drift, and policy compliance.

A 06Adapt

Crystallises patterns into scheduled automations.
